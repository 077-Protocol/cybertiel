2. PRESERVE THE FAILED v25-r2 INSTALLATION
Your earlier report showed Docker active and no installer process. Check again:

  pgrep -af 'setup-cybertiel|install-cybertiel|verify-pi-lock' || true
  sudo systemctl is-active docker
  sudo python3 tools/archive_partial_v25_r2.py

The helper prints a plan. It verifies old managed markers and the original lock,
refuses READY/project data/managed containers/active installers, and holds the
installer's private coordination lock. Inspect its proposed backup destinations.
After that independent review, preserve the partial directories:

  sudo python3 tools/archive_partial_v25_r2.py --apply

This renames /opt/cybertiel and, if present, /srv/cybertiel to timestamped backups
beside the originals. It deletes nothing. It leaves Docker installed and running.
If refused, investigate its reason; do not change markers, delete READY, remove
locks or disable a gate. Retain the backups until the new install is qualified.
On a fresh server without partial managed directories, skip step 2.

3. PLAN, THEN INSTALL THE REPAIRED PACKAGE
From the same extracted package directory:

  bash preflight-server.sh
  bash setup-cybertiel.sh --plan
  sudo bash setup-cybertiel.sh --install --accept-official-q8

The install changes host packages, downloads large assets and builds containers.
If the existing host update/reboot gate requires reboot, reboot normally, return
to this same package directory and repeat the setup install command. Do not rerun
the v25-r2 archival helper against a partial v25-r3 installation; the same v25-r3
installer can resume its own partial managed directories.
